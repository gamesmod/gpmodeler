# 9. Как применить это в gpModeler

gpModeler хранит MPP-параметры прямо в модели и генерирует по ним DDL нужного диалекта.

## Тип сервера

Откройте свойства базы данных и выберите **Server flavor**: PostgreSQL, Greenplum 6, Greenplum 7
или Apache Cloudberry. Выбор сохраняется в файле `.dbm` и включает в диалогах таблиц вкладку
**MPP**. От него зависит синтаксис хранения:

* для Greenplum 6 — `WITH (appendoptimized = true, orientation = ..., compresstype = ..., compresslevel = ...)`;
* для Greenplum 7 и Cloudberry — `USING ao_row | ao_column | pax` и параметры сжатия в `WITH (...)`.

## Вкладка MPP в свойствах таблицы

| Поле | Что задаёт | Рекомендации |
|---|---|---|
| **Distribution** | `HASH` (`DISTRIBUTED BY`), `RANDOMLY`, `REPLICATED` или «Default» (без предложения в DDL, решает сервер) | не оставляйте «Default» для больших таблиц (раздел 3) |
| **Key columns** | колонки ключа распределения через запятую, например `account_id`; поле активно только для `HASH` | одинаковые колонки и типы у таблиц, которые соединяются (раздел 3) |
| **Storage** | Heap, Append-optimized row, Append-optimized column, PAX (Cloudberry) | раздел 5 |
| **Compression** | `zstd`, `zlib`, `quicklz`, `rle_type`, `none` или пусто (значение сервера) | `zstd` по умолчанию; `quicklz` только для Greenplum 6, `rle_type` только для колоночного хранения (раздел 5) |
| **Compression level** | уровень сжатия, «Default» — значение сервера | 3–5 для основных таблиц фактов |

## Порядок работы

1. Нарисуйте логическую модель: сущности, атрибуты, ключи, связи (раздел 1). Внешние ключи
   рисуйте, даже если сервер их не проверяет: по ним строится диаграмма и видна структура.
2. Выберите тип сервера в свойствах базы данных.
3. Определите оси распределения и задайте политику для каждой большой таблицы; мелкие
   справочники пометьте `REPLICATED`.
4. Проверьте первичные ключи и уникальные ограничения: они должны включать ключ распределения.
5. Задайте хранение и сжатие.
6. Сгенерируйте SQL (экспорт в файл) и пройдитесь по чек-листу из раздела 8.
7. Разверните модель в тестовой базе, загрузите выборку данных, проверьте перекос и планы
   ключевых запросов через `EXPLAIN`.

Секционирование в синтаксисе GP/CB (`START/END/EVERY`), внешние таблицы и PXF, группы ресурсов
пока в планах развития gpModeler. До их появления такие объекты можно описать объектом
Generic SQL или пользовательским SQL таблицы (Custom SQL), либо поддерживать отдельными
скриптами миграций.
