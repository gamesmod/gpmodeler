# gpModeler

<img src="assets/conf/pgmodeler_logo.png" alt="gpModeler" width="128" />

**gpModeler** is a database modeling tool for **Greenplum** and **Apache Cloudberry**, forked from
[pgModeler](https://github.com/pgmodeler/pgmodeler) (GPLv3). It is not affiliated with or endorsed
by the pgModeler authors, Nullptr Labs, the Greenplum or the Apache Cloudberry projects.

## What differs from pgModeler

* **Server flavor** per model: PostgreSQL, Greenplum 6 (PostgreSQL 9.4 syntax), Greenplum 7 (PostgreSQL 12)
  or Apache Cloudberry (PostgreSQL 14). Set it in the database properties dialog; it is saved in the `.dbm` file.
* **Table distribution**: `DISTRIBUTED BY (...)`, `DISTRIBUTED RANDOMLY`, `DISTRIBUTED REPLICATED`.
* **Table storage**: heap, append-optimized row/column (`ao_row`, `ao_column`), PAX, with compression type and level.
  Greenplum 6 gets `WITH (appendonly=true, orientation=...)`, Greenplum 7 and Cloudberry get `USING <access method>`.
* The Windows distribution bundles `libpq` (the only database driver used; Greenplum and Cloudberry speak the PostgreSQL protocol) with its dependencies.
* Own configuration directory (`gpmodeler-2.0`), executables `gpmodeler`, `gpmodeler-cli`, `gpmodeler-ch`, `gpmodeler-se`.

Planned: GP/CB partitioning (`START/END/EVERY`), external tables and PXF, resource groups/queues and reverse engineering from the `gp_*` catalogs.

## Download

Windows builds (`gpmodeler-win64.zip`) are attached to the [releases](https://github.com/gamesmod/gpmodeler/releases)
of this repository. Every push also produces the same archive as an artifact of the `Windows build` workflow.

## Build

Requirements: CMake 3.16+, a C++ compiler with GCC/Clang extensions (MSVC is not supported), Qt 6.6+
(Core, Gui, Network, PrintSupport, Svg, Widgets), libpq and libxml2.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DPGM_PREFIX="$PWD/dist/gpmodeler"
cmake --build build --parallel
cmake --install build
```

On Windows the reference setup is MSYS2 with the clang toolchain; see `.github/workflows/windows-build.yml`
for the exact packages and the steps that bundle Qt and `libpq.dll` next to the executables.
The icons are generated by `assets/branding/gen_icons.py`.

## Known issues

Inherited from pgModeler:

* Very large models (hundreds of tables) may render slowly because of the Qt raster engine.
* Uppercase names, special characters and reserved keywords are always emitted as quoted identifiers.
* Very large exports or validations may still hit race conditions in rare cases.
